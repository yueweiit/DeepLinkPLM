# Readable phone-model details across partner catalogs

Supplier, sample-selection and listed-product catalogs share the existing read-only phone-model dialog. Detail links are actionable for one, two and large sets. Equivalent names with the same brand and full model code appear once; original member IDs and stored selections remain intact. Different network versions, hole variants and codes remain separate. Combined compatibility descriptions are collapsed by default and counted separately from individual phones. Searching an alias finds its displayed model.

The existing component and shared phone-name parser are reused. The delta contains seven production files and three existing test files; no added or deleted application files, dependencies or backend inputs. All 832 backend source inputs, including the case-insensitive login fix and its PostgreSQL test, remain identical to the preceding release.

284 unique relevant frontend cases passed across seven files. The final 21-case component rerun is not added to that total. A fresh type check and production build passed after merging the exact ten paths. Local browser checks use the real Vue component with synthetic inputs at 1788, 1000 and 900 by 870; those checks do not claim production-data or complete business-page coverage. The release preserves the backend process, static asset compatibility, accounts and business records, with no new schema, backup or fixture import.
