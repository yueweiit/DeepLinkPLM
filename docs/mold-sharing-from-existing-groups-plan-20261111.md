# 从模具管理建立共模映射的小增量方案

日期：2026-11-11。状态：方案文档，尚未实施。本次仅新增本文档，不修改业务代码、数据库数据或本地运行服务。

## 1. 目标与已确认口径

工程人员已在系统外完成人工适配核验，在「基础资料 → 共模映射 → 新增共模映射」中选择「模具管理」已有模具组，即可首次建立或继续追加共模关系。不能因为缺少制造关系、旧编码不含孔型或尚无新编码，就让已有模具组无故消失。

已确认的规则：

- 基准资料来自「模具管理」，不要求用户先创建制造关系，也不要求该组已经有两个机型。
- 旧编码没有孔型信息时，由工程选择大孔、精孔或混合；已有明确孔型则沿用。
- 没有新规则编码时可以生成，已有同实体的新编码则复用；保留历史原码和来源。
- 多个机型共用同一套实体模具，映射码分别用于识别机型，最早原模具编码作为主码。
- 原来完全没有完整编码的部件，以工程确认的基准机型生成首次主码。
- 工程确认后直接生效，不新增钉钉审批或额外申请。
- 不新建实体模具套，不增加开模成本，不合并成品、SKU或库存。

## 3. 数据对象与选择方式

- 模具组：`plm_collaboration_item.item_id`，是模具管理的主档，不能仅用名称作为身份。
- 具体模具套：`plm_collaboration_mold_set.mold_set_id`。同组可能有多套，必须明确选中的具体实体套，不能默认为所有套。
- 部件：`plm_collaboration_mold_part` 的PC和TPU，分别生成/关联编码，但仍只是一套实体模具。
- 逐套适配：`plm_collaboration_phone_set_compatibility`，记录某手机对某套模具PC/TPU的确认事实。
- 制造关系：`plm_manufacturing_relation`，记录产品、手机、孔型、结构与实体套关系；本次由工程确认事务补齐，而不是前置录入门槛。
- 实体身份及映射：`plm_mold_entity_identity`、`plm_mold_entity_code_mapping`，继续承载原主码及每款手机的模具映射码。

组、套、机型都通过ID关联。手机四位码读取已有主数据，保留前导零；名称仅用于搜索和展示，不通过模糊名称推断适配关系。

保持单一列表，列仍为：模具编码、孔型、适用机型、共用的模具编码、状态；不显示SKU，不新增第二张表。

```text
新增适用机型 *         [从手机主数据选择            ▼]
新规则编码预览         PC/TPU：基准机型码、新增机型码、实体主码
工程确认依据 *         [                          ]
确认原因 *             [                          ]
                              [取消] [确认并生效]
```

交互约定：

1. “已有共模机型”改为“已有模具组”，去掉首次录入时“组内任一已确认机型”的前提性表述。
2. 候选从模具管理同源读取；没有制造关系或新编码也允许展示，标出“待补编码”“待确认孔型”等具体情况。
3. 只有一套时自动选中并显示；多套必须明确选择。没有具体套的主档显示“请先在模具管理登记已有实物套”，本分支不暗中新建套。
4. 基准机型优先从所选具体套的成员中选择，同组多机型任选其一可追加映射，但实体主码不随所选成员变化。
5. 若主档只有旧名称/手机码而没有成员ID，允许工程通过现有手机选择器明确选择并确认基准机型，本次提交补齐成员及逐套适配；不按名称自动匹配。
6. 已有明确孔型自动带出并锁定；尚未明确时人工选择。不同明确孔型不合并为同一实体。
7. 修改产品、组、套、机型或孔型后清空旧预览；慢请求返回不得覆盖新选择。
8. 只有待补编码的pending槽位可以进入本次工程登记，登记编码不会自动把部件状态改成ready、验收通过或已入库。确实缺少某实体部件时不能冒充整套共模。
9. 不新增人工核验勾选框或审批步骤；确认依据和提交动作记录工程已完成的核验事实。

## 5. 编码规则与原码保留

依据仓库根目录 `coding-rules.md`、`coding-rules-system-implementation.md` 的v2优先规则。所有生成和解析复用 `ProductBusinessCodeGenerator`，不另写前端拼码器。

```text
新模具码 = M + 产品特定码2位 + 材质2位 + 孔型1位 + 手机码4位
材质：TPU=10，PC=20；孔型：大孔D，精孔J，混合H。
历史完整码 = M + 产品特定码2位 + 材质2位 + 手机码4位。
```

超级队长产品编码为MHA，产品特定码为HA；示意基准机型1291、新增机型1292、精孔：

| 部件 | 历史完整码（若存在） | 基准机型新规则码 | 新增机型映射码 |
| --- | --- | --- | --- |
| TPU | MHA101291 | MHA10J1291 | MHA10J1292 |
| PC | MHA201291 | MHA20J1291 | MHA20J1292 |

上述为规则示例，不是待写入本地库的数据。

逐部件处理：

| 已有资料 | 保存策略 |
| --- | --- |
| 已存在明确实体身份/主码 | 沿用已锁定主码，不因换选组内机型重置 |
| 有完整九位旧码，无新规则码 | 旧码作为原主码保留，补基准和新增机型新规则映射码 |
| 已有匹配的新规则完整码 | 复用；同实体同机型不重复生成 |
| 无完整码 | 按明确基准机型生成首次新规则主码，新增机型生成别名 |
| 只有五位前缀或非标准原刻字 | 原值留在原字段作为历史证据，不能冒充完整主码；生成新的完整主码并记录与原值的关联 |
| 编码相互矛盾或已属另一实体 | 展示具体冲突，保留原值；不能把冲突视为无编码并覆盖 |

“最早”以已有明确主码和可追溯来源为准，不按手机码最小值、字符串排序或当前点击顺序推断。有多条相互冲突的完整历史主码且无确定归属时返回具体待核对信息。

孔型不从旧九位码推断，`other`不等于H。新增机型和基准机型的新规则码可以不同，但指向同一实体套与对应部件。

编码生成不代表产生库存。成品/SKU公式及自身手机码不变；生产涉及的模具编码使用对应机型映射码，追溯时解析至实体主码和套ID。

## 6. 新增接口与兼容策略

保留现有制造关系接口及 `/mold-share-mappings/entities/preview`、`/entities/confirm` 请求/响应语义。新增三个独立端点供本次页面使用，路径为拟定名称：

| 新端点（均位于/api/v1/mold-share-mappings） | 用途 |
| --- | --- |
| GET /existing-groups | 分页查询所选产品模具组，返回可选套、成员、原码、孔型及资料缺口 |
| POST /existing-groups/preview | 从组、套、明确基准机型计算补码及映射计划，无业务写入 |
| POST /existing-groups/confirm | 工程确认，事务内重新校验并保存 |

候选参数：productLineId、keyword、page、size。孔型未知的组不因已选孔型而消失；已知孔型按实体事实筛选。列表使用分页搜索，不能只取前100条就当作全部候选。

预览/确认输入：productLineId、itemId、moldSetId、referencePhoneModelId、targetPhoneModelId、holeType；必要结构范围沿用原实体关系，未设置时为空，不新增强制结构说明输入。确认另含evidence、reason、预览返回的sourceDigest。

sourceDigest绑定主档/套状态与版本、成员适配、部件编码、现有实体身份、产品和手机码、选定孔型，确认时重算；不信任前端提供的任何最终编码。已关联但未启用的机型不能生成新码。

返回预览包含：来源组/套、逐部件原值、实体主码、基准码、目标映射码、每项“沿用/补码/新建身份”的动作及缺失项。确认响应沿用现有mappings核心字段并附itemId、moldSetId，便于列表刷新与定位。

## 8. 调用链及保存顺序

```text
共模页面选择产品
 → GET existing-groups
 → 与模具管理同源的主档/套/逐套成员资料 + 已有实体孔型
 → 选择模具组、具体套、基准机型、孔型、新增机型
 → POST existing-groups/preview
 → 校验可见范围与生命周期 → 生成只读计划和sourceDigest
 → 页面显示原码、基准新码、目标映射码、实体主码
 → 工程填写依据/原因 → POST existing-groups/confirm
 → 工程权限 → 锁定来源和占号范围 → 重算计划与摘要
 → 原码登记/首次主码登记 → 部件编码补链
 → 基准及新增手机的逐套适配登记
 → 实体身份、机型映射码与有效制造关系
 → 审计及版本更新 → 提交事务
 → 刷新共模列表；模具管理再打开可见已补齐资料
```

事务要求：

- 预览不创建关系、编码主档、预留或占号记录。
- 确认使用与现有共模代码一致的锁顺序、唯一性规则，重查编码主档、预留、申请及映射占用。
- 编码主档绑定到现有且确定的产品归属，优先保留已有product_id；无型号产品时以已选产品线登记，不为共模额外创建型号/SKU。
- 原刻码字段不被新生成码覆盖；部件已有原值必须保留，正式码通过对应主档ID关联。
- 逐套适配保留其他成员及其他套记录，只新增/明确本次基准和目标机型的适配事实。
- 新增制造关系使用shared_material=false、manufacturing_product_id=null、sku_ids=[]，不触发共用生产物料逻辑。
- 保存后再次用现有制造身份解析验证本次映射可解析；失败则事务全部回滚。
- 同实体相同范围重复提交复用原记录；同码属于其他实体、旧版本、停用实体、不同孔型或主码矛盾时明确报错。
- 主档/套版本及历史按现有方式更新，审计记录来源ID、孔型、原码、新码、操作者、依据、原因和本次动作。

## 10. 测试业务流与验收标准

实施时先在隔离库测试；本地8111只读检查候选与预览，真实写入使用用户指定的实际组或经明确授权的验收数据。本次文档阶段不进行业务写入。

| 场景 | 操作及预期 |
| --- | --- |
| 有模具组，无制造关系、无编码 | 可看到组和具体套；明确基准机型/孔型后预览首次主码和目标映射码，工程保存成功 |
| 有完整旧码、无孔型 | 旧码原样展示；工程选孔型后生成基准和目标新码，原主码及原刻字不变 |
| 有新规则码 | 复用原实体身份/同机型码，不重新编码 |
| 多机型共用 | 选任一已有成员再加入第三机型，实体主码和moldSetId不变 |
| 同组多套 | 必须明确套；映射只落到选定套，不给其他套补适配 |
| 历史名称但无成员ID | 提示明确选择基准手机，不按名称猜码；工程确认后可在模具管理看到成员 |
| 孔型明确/未知 | 明确孔型自动沿用；未知允许人工选择；不同明确孔型不能混入同实体 |
| 只有五位目录前缀 | 原值保留，新完整主码另行生成，不把前缀当实体主码 |
| 编码被其他实体占用 | 显示具体冲突码，事务不留半成品关系或部分编码 |
| 并发、重复、来源变化 | 重复确认幂等；来源变化要求刷新预览；并发不会重复建实体或抢走别人的编码 |
| 单部件适配 | 不能以只有PC适配通过整套PC/TPU共模；提示具体缺失，不创建虚构TPU |
| 权限与生命周期 | 无工程维护权限不能确认；越权、停用组/套、停用手机不能新建映射 |
| 回归旧路径 | 原entities预览/确认、开模沿用、新开、加开一套行为不变 |
| 生产身份 | 分别解析基准及目标PC/TPU映射码，均返回相同对应实体和套；模具流转保留当前机型映射码 |
| 数量与库存 | 确认前后实体套数量、开模费用、成品/SKU编码和库存余额不变化 |

构建与测试：前端定向测试、类型检查和生产构建；后端新分支及既有编码/实体映射测试；隔离库HTTP验证补链、幂等和事务回滚；8111浏览器检查候选、预览、单表和刷新效果。未执行真实生产工单时，交付说明必须区分“身份解析通过”和“真实工单流转通过”。

## 11. 实施顺序及回退

1. 新增组来源候选接口，核对与模具管理同产品、同权限下的组/套一致性。
2. 新增只读计划与预览，覆盖旧码、缺码、孔型未知和多套场景。
3. 新增事务确认补链和审计，复用生成器及现有实体模型。
4. 前端切换至新分支，保留原接口供原调用方继续使用。
5. 完成测试后发布本地8111，并输出实际可见效果及测试记录。

回退优先切回旧页面/旧服务镜像，保留已确认的新增数据和审计，旧接口继续可用。不通过删除映射、回写原码或减少模具套数量回退；已经被业务引用的关系按现有停用流程处理。

## 12. 交付预期

用户可以从系统已有模具组开始建立第一条共模映射，无需先找另一个入口维护制造关系。孔型由工程确认，旧码保留、缺码生成，新增机型映射到原实体套；再次从组内任一成员追加时保持相同主码和实体。页面与后端保存结果一致，生产身份可追溯，并保持老接口和原生产物料分支的行为。
