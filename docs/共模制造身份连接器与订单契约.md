# 共模制造身份：连接器与订单交接契约

## 边界与编码含义

手机资料的 `1218` 表示客户选择的18 Pro Max，不会改成1145。工程确认某个款式、孔型及具体模具后，可以引用原1145制造型号产品和明确的SKU范围；共模本身不能授权共用成品。

本仓库的 `services/dingtalk-mold-sync/central_mold_codes.py` 复用原中央编码适配器改造，仅处理HTTP请求与响应，不含SQL分号器或本地编码生成器。本次源来自共享仓库原适配器审阅后的增量，不代表远端运行脚本已更换、中央编码已启用或生产模板已适配。

## 钉钉模板字段

| 字段 | 新审批要求 | 来源及含义 |
| --- | --- | --- |
| 新品／款式 | 必填 | 原项目或产品，不按手机名称猜配 |
| 孔型 | 必填 | 大孔、精孔、其他；其他必须说明结构 |
| 本次办理方式 | 必须如实表达 | 新开、加开、沿用或待工程确认；待确认不能自动执行 |
| 适用手机 | 尚未明确可后补 | 标准手机成员，可多个；不是生产编码替换表 |
| 原模具依据 | 沿用时明确 | 档案、实物套和逐套PC／TPU依据 |
| 原制造物料依据 | 共用成品时明确 | 原制造型号产品、允许的SKU范围、确认关系及版本 |
| 生产编码 | 工程确认后的结果 | 不从申请手机四位编号直接推导；未定时不虚填 |
| 图片、附件、日期 | 按对应审批模板 | 保留原附件版本、采用关系及原有必填规则 |

用户调整模板后再读取真实组件ID和版本做映射，不猜ID、不自动改生产模板。旧审批继续读取自己的快照。新增模板映射未通过联调时，不启用其正式提交。

## 编码连接器

仍使用 `POST /api/v1/integrations/dingtalk/mold-code-reservations`，保留原Bearer鉴权、中央编码开关和稳定 `requestId`。不得由连接器任意绑定PLM申请或借用某个工程师身份。

新请求同时携带以下事实：

```json
{
  "requestId": "isolated-example-stable-id",
  "tipo": "已配置类型",
  "model": "Apple iPhone 18 Pro Max",
  "intent": "reuse",
  "productLineId": 55,
  "phoneModelId": 18,
  "holeType": "large",
  "structureDescription": "已确认结构规格",
  "relationId": 7,
  "relationVersion": 3
}
```

以上ID仅为隔离示例，不是生产关联指令。`new` 不携带复用关系；`reuse` 必须有明确关系及版本。缺少办理意图的旧三字段请求不能静默当作新开。标准手机、产品、孔型、权限或关系依据不齐时，应返回待核对，不在本地生成1218的另一套码。

确认结果区分：

- `businessPhone`：客户适用手机，例如1218。
- `moldPhoneCode`：原完整M码中的机型段，例如1145。
- `manufacturingPhoneCode`／`manufacturingProductId`：确已确认的制造物料身份；仅共模时可以为空。
- `materialResolutionStatus`：共用物料是否已确认；不能用M码存在替代该确认。
- `moldCodes`／`generatedCodes`：服务器返回的正式原码。
- `relationId`／`relationVersion`：本次采用的明确依据。

Python旧返回键 `phone_code` 为兼容保留，仅与 `mold_phone_code` 同义，不能用它生成N码、成品、SKU或发货指令。后续调用方改用明确字段并确认无旧键引用后，可删除此别名。HTTP失败、结果待定、返回其他手机或关系版本时，重试同一请求ID，不退回旧SQL分号器。

连接器令牌不自动具备国内工程对象权限。生产开关保持原值；只有真实权限、模板与隔离联调通过后才能另行启用。

当前边界尚未配置独立且有对象授权的集成身份，预留接口不会为令牌请求分配编码：开关未启用则拒绝，启用后缺少身份依据仍返回 `pending`。本地适配器的成功响应测试验证的是上述交接契约，不代表远端脚本已联调。`new_set` 加开执行目前通过 PLM 工程办理；本适配器不会将它降级成 `new`。

## 销售订单制造快照

`POST /api/v1/manufacturing-order-snapshots/preview` 是已登录且获对象授权的国内用户使用的只读边界。它不新增订单台账，不保存订单，不上架，不预占库存，不下生产单或发货。

输入包括：`productLineId`、`customerPhoneModelId`、`holeType`、`structureDescription`、`relationId`、`relationVersion`、`manufacturingSkuId`、`externalSource`、`externalOrderId`、`externalLineId`、`externalSpecId` 和可选的客户原文 `customerChoiceText`。

服务复用同一制造身份解析，要求共用生产物料已确认、版本一致、SKU确实在允许范围内；仅确认共模不能通过。结果包含客户手机、孔型、关系版本、原模具部件、实际制造SKU及内容校验值。客户选择18 Pro Max不会被改写为17 Pro Max，制造SKU则可继续引用1145。

响应固定说明 `externalListingConnected=false`、`productionWriteEnabled=false`、`orderSaved=false`。真正的外部销售订单拥有者应在其原订单保存事务中保存完整 `snapshotJson` 与 `snapshotSha256`，而不是只存一个会随维护变化的当前关系ID。校验值用于识别内容变化，不是权限或发货授权凭证。

已经确认的订单必须读取当时保存的快照；新增订单重新解析当前关系。不得通过重新生成快照静默替换旧订单物料。缺少手机选择的历史1145订单不能反推出17／18销量。

外部商城、ERP／MES订单和库存接口当前未在本边界中接通，必须按实际接口隔离验证后由各自原写入流程接续，不能把只读预览冒称为外部生产生效。
