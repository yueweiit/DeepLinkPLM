# Development costs by specification

Development projects can keep separate cost drafts and versions for explicitly defined specifications. Shared costs remain separate from unassigned historical estimates; adding compatibility does not create another physical mold or duplicate its cost. The existing project list layout and independent approval records are retained.

The cost editor reuses the original save, permission, audit and BOM workflows. Source workbook figures are available through a details entry without repeating explanations in each row. Existing ungrouped versions remain usable, and finalization checks only the explicitly selected applicable versions while retaining the original BOM and supplier checks.

Validation: 416 frontend cases passed, type checking and production builds passed. Backend regression discovered 328 cases: 295 passed and 33 existing environment-dependent cases skipped. Normal Spring startup and Flyway 116-to-117 were checked on isolated PostgreSQL. Three window widths were checked with the sidebar expanded.

The additive migration adds three nullable scope columns, two checks and one lookup index, and replaces two uniqueness indexes. Original rows remain unassigned; no existing amounts are distributed automatically. Existing ungrouped consumers remain until explicit scope-aware adoption is completed. No real approval was submitted and no actual expense was inferred.
