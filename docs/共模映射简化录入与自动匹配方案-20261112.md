# 共模映射简化录入与自动匹配方案

## 一、方案目标

将「基础资料 → 共模映射 → 新增共模映射」从当前需要理解模具组、具体模具套、实体主码等内部概念的表单，简化为工程人员熟悉的业务字段。

页面仅要求填写：

1. 产品
2. 已开模机型
3. 新增适用机型
4. 孔位类型
5. 材质，可多选 PC、TPU
6. 工程确认依据
7. 确认原因

模具组、模具套、内部 `itemId / moldSetId`、实体身份及编码关联全部由系统后台自动匹配，不再作为普通表单字段展示。

## 二、业务定义

### 2.1 已开模机型

已经存在实际模具，并由工程确认可作为共模来源的手机型号。

### 2.2 新增适用机型

准备加入共模关系、继续使用已有实体模具的新手机型号。

### 2.3 孔位类型

- 大孔：`large / D`
- 精孔：`precision / J`
- 混合孔：`mixed / H`

### 2.4 材质

- TPU：材料码 `10`
- PC：材料码 `20`
- 页面支持多选；只处理本次选择的材质。

### 2.5 实体模具匹配

系统根据“产品 + 已开模机型 + 孔位类型 + 所选材质”查询已有模具管理数据、制造关系和共模实体映射，确定实际的 `itemId + moldSetId + entityId`。

## 三、预期页面效果

```text
新增共模映射

产品              [请选择产品]
已开模机型        [请选择已经有模具的机型]
新增适用机型      [请选择准备加入共模的机型]
孔位类型          [大孔 / 精孔 / 混合孔]
材质              [√ TPU] [√ PC]

自动匹配结果
符合条件的实体模具：1 套
TPU：原模具编码 → 新机型映射编码
PC ：原模具编码 → 新机型映射编码

工程确认依据      [请输入]
确认原因          [请输入]

                 [取消] [确认并生效]
```

页面不再直接展示：

- 已有模具组
- 具体模具套
- `#952 / #596` 等内部主键
- 实体身份编号
- 制造关系编号

## 四、自动匹配规则

### 4.1 查询条件

以以下字段作为固定匹配条件：

- `productLineId`：产品
- `referencePhoneModelId`：已开模机型
- `holeType`：孔位类型
- `materialCodes`：所选材质集合
- 状态必须为有效

### 4.2 匹配优先级

1. 优先查找已生效的实体共模映射。
2. 未找到实体映射时，查找已开模机型的有效制造关系。
3. 仍未找到时，查询模具管理中已登记该机型的模具组和实体模具套。
4. 历史模具尚未登记制造关系，但存在完整 PC/TPU 实体部件时，允许进入工程补链分支。

### 4.3 匹配结果处理

#### 唯一匹配

找到唯一符合条件的实体模具套时，系统自动选中并返回编码预览，用户不需要选择模具组或模具套。

#### 无匹配

提示：

> 未找到该已开模机型对应的有效实体模具，请先在模具管理中补充模具资料。

不允许确认，不自动创建空模具组或虚拟模具套。

#### 多个匹配

不自动猜测。页面仅在此时显示一个异常选择区域：

```text
找到多套符合条件的实体模具，请选择实际共用模具：
[第 1 套 · 原模具编码 XXX]
[第 2 套 · 原模具编码 YYY]
```

该选择属于异常分支，正常唯一匹配场景不展示。

### 4.4 材质多选规则

- 选择 TPU：只验证和生成 TPU 映射。
- 选择 PC：只验证和生成 PC 映射。
- 同时选择 TPU、PC：两种材质必须都能落到同一模具套，否则禁止确认。
- 不再强制所有共模操作必须同时具有 PC 和 TPU；按本次选择的材质处理。
- 未选择材质时不允许预览或确认。

### 4.5 冲突规则

以下情况必须阻止确认：

- 已开模机型与新增适用机型相同。
- 同一产品、机型、孔位和材质指向多个不同实体模具。
- 已有映射编码被其他实体模具占用。
- 所选 PC 和 TPU 分别匹配到不同模具套。
- 模具组、模具套、部件、实体身份或制造关系已停用。
- 预览后源数据发生变化。

## 五、编码规则

继续复用现有 `ProductBusinessCodeGenerator`，不建立第二套编码逻辑。

```text
M + 产品特定码 2 位 + 材质 2 位 + 孔位标识 1 位 + 手机码 4 位
```

- TPU：`10`
- PC：`20`
- 大孔：`D`
- 精孔：`J`
- 混合孔：`H`

旧的完整模具编码继续作为实体主码，不重新编码；新增适用机型按新规则生成映射码，映射码和旧机型编码均指向同一实体模具。

## 六、接口设计

保留现有接口，不修改原请求结构和行为：

- `GET /api/v1/mold-share-mappings/existing-groups`
- `POST /api/v1/mold-share-mappings/existing-groups/preview`
- `POST /api/v1/mold-share-mappings/existing-groups/confirm`
- 原实体映射、老共模维护和开模申请接口继续保留。

新增独立简化分支：

### 6.1 自动匹配预览

`POST /api/v1/mold-share-mappings/auto-match/preview`

请求：

```json
{
  "productLineId": 50,
  "referencePhoneModelId": 121,
  "targetPhoneModelId": 122,
  "holeType": "precision",
  "materialCodes": ["10", "20"]
}
```

响应：

```json
{
  "matchStatus": "unique",
  "candidateCount": 1,
  "matchToken": "服务端签发的预览摘要",
  "matchedMold": {
    "itemId": 952,
    "moldSetId": 596,
    "displayName": "第 1 套"
  },
  "codes": [
    {
      "materialCode": "10",
      "primaryCode": "MFA10J0121",
      "sourceMappingCode": "MFA10J0121",
      "targetMappingCode": "MFA10J0122"
    }
  ]
}
```

当存在多个候选时，响应返回简化候选列表；候选内部仍携带 `itemId / moldSetId`，但页面只显示套号、原模具编码、状态等业务信息。

### 6.2 自动匹配确认

`POST /api/v1/mold-share-mappings/auto-match/confirm`

请求：

```json
{
  "productLineId": 50,
  "referencePhoneModelId": 121,
  "targetPhoneModelId": 122,
  "holeType": "precision",
  "materialCodes": ["10", "20"],
  "selectedMoldSetId": 596,
  "matchToken": "预览返回的摘要",
  "evidence": "工程已确认孔位和结构一致",
  "reason": "新增机型共用已有模具"
}
```

唯一匹配时 `selectedMoldSetId` 可以不传；多匹配时必须传入用户选择的模具套。

## 七、后端调用链路

```text
MoldShareMappingView.vue
  → previewAutoMatchedMapping()
  → POST /mold-share-mappings/auto-match/preview
  → MoldShareMappingController.autoMatchPreview()
  → MoldShareAutoMatchService.preview()
  → MoldShareAutoMatchRepository.findCandidates()
  → 查询实体映射 / 制造关系 / 模具管理主档
  → ProductBusinessCodeGenerator 生成编码预览
  → 返回唯一、无匹配或多匹配结果

确认并生效
  → confirmAutoMatchedMapping()
  → POST /mold-share-mappings/auto-match/confirm
  → MoldShareAutoMatchService.confirm()
  → 重新锁定并校验候选与 matchToken
  → 按所选材质补实体身份及映射码
  → 补手机与模具套适配、制造关系
  → ManufacturingIdentityService.requireResolved()
  → 写协作历史和操作日志
```

8. 部署到本地 8111，验证页面和测试业务流。

## 十二、验收标准

- 普通用户不需要理解模具组、模具套和内部编号。
- 唯一匹配场景只填写产品、两个机型、孔位、材质和确认信息即可完成。
- 无匹配时不生成虚假模具数据。
- 多匹配时系统不自动猜测，必须人工选择实际实体模具。
- 材质支持 PC、TPU 单选或多选。
- 只为所选材质生成映射和适配关系。
- 新旧机型映射码能够解析到同一实体模具。
- 工程确认后直接生效，不发起钉钉审批。
- 老接口、老数据和原共模映射列表继续正常使用。
